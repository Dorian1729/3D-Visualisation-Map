# 数据下载项目梳理

以本地文件和脚本为证据，用用户的语言解释数据是什么、从哪里来、如何下载、目前下载到什么程度。用户只要求检查或整理时，保持只读；下载、修复和转换仅在用户要求时执行。

## 检查与判断

- 先查看目录、项目说明、相关索引、下载脚本和报告。对大目录汇总文件数、扩展名和字节数，仅展示少量样本；不递归打印全部文件或整份大型 GeoJSON。
- 区分空间索引、模型或影像载荷、脚本、日志和临时文件。GeoJSON、SHP、GPKG、GML、KML、FGDB 可能是同一索引的不同导出格式，也可能包含不同数据；通过要素数、字段、标识符和范围核实，不能只凭目录名判定。
- 显式按 UTF-8 读取 JSON 和中文文本；PowerShell 读取时指定 `-Encoding UTF8`。解析失败时先检查编码和有限的错误上下文，不把整份数据输出到终端。
- 从索引提取要素数、唯一分块数、区域字段、坐标系及范围、下载 URL 字段、可选格式和缺失链接。区分要素数量与去重后实际下载任务数，保留分块名称及 URL 的大小写。
- 阅读脚本还原输入、筛选条件、格式默认值、并发、重试、输出目录、跳过规则、校验、报告生成时机，以及临时文件处理。不要为了了解行为直接执行下载器；即使 `--dry-run` 也可能创建目录，先读代码。
- 抽查压缩包的成员清单，按实际内容解释用途，例如 OBJ 几何、MTL 材质及 JPG 纹理，或 tileset.json 与三维瓦片。默认不解压大型数据，不执行包内程序。读取 ZIP 目录不等于完成 CRC 完整性校验。
- 从本地 URL 和元数据定位发布机构与官方说明；需要核实来源、产品定义或年代时访问对应官方页面，并在结果中附来源链接。网页无法访问时，明确区分本地记载和已联网核实的内容。不把采集时间、数据更新时间、文件修改时间和下载时间混为一谈。

## 下载状态和复用命令

- 分别统计正式文件、零字节文件和 `.part` 等临时文件，容量明确使用 GB（10^9）或 GiB（2^30）。正式扩展名只能说明文件已落盘，不能替代完整性检查。
- 将实际文件对应到索引中的分块和格式，再计算进度；不要把多个格式或临时文件重复算成已完成分块。只下载一个区域时，应区分该区域目标和全索引目标。
- 如果怀疑仍在下载，间隔进行两次轻量快照，或在环境允许时查看相关进程。文件增长只支持“可能仍有写入”；临时文件或缺少报告本身不证明程序已停止或下载失败。
- 分开表述“脚本支持的流程”“现有文件与该流程一致”和“有日志证明的历史命令”。没有运行记录时，不声称知道用户当时输入的命令或最初获取索引的操作。
- 给出适配当前脚本的示例命令，说明运行目录、所需运行时、选区或格式参数，以及输出位置。先核对覆盖和重复下载行为。
- 区分跳过完整文件与 HTTP 字节级断点续传；检查 Range 请求和临时文件打开模式后才能声称支持续传。重新以 `wb` 写入 `.part` 表示从头下载。
- 如果默认目录非空会另建新目录，继续已有任务的示例应显式指定原输出目录。若可能有活跃任务，提醒避免同时向同一路径写入，不自动启动第二个下载进程。
- 不将示例项目的分块数、地区、URL 字段名、格式默认值或容量套用到其他项目。所有数字都重新读取，并注明快照时间或检查时状态。

## 交付

先用一句话说明项目用途，再给出文件分类、数据来源与覆盖、当前下载状态、下载流程和必要的复用命令。尽量使用简明中文和小表格，附关键本地文件链接。对未校验的完整性、无法还原的历史和来源访问失败给出具体限度。

用户要求保存文档时，在项目内生成中文 Markdown，使用相对路径以方便迁移；已有说明与实测结果冲突时，说明差异，避免悄悄把历史描述当成当前状态。只问“看看”时不必创建报告文件。
